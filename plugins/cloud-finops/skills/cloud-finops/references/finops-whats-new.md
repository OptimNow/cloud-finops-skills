# What changed - verified provider changes, rolling 90 days

> A dated digest of the provider and vendor changes that affect a cloud or AI bill:
> what changed, when, and which guide carries the detail. It covers the last 90 days
> and the changes already scheduled. It lists what this library verified on the
> providers' own pages, not every announcement.

---

## How to use this digest

- **Say the date first.** The digest is reconciled on the date printed under this
  section. Anything a provider announced after it is not here: say so, and for the days
  since, point to the provider's own "What's New" page.
- **Answer in the shape asked.** "What happened last month" is that month's table.
  "What did AWS change" is the AWS rows across the tables. "What is coming" is
  "Scheduled changes". Give each item its date, its effect on the bill in one sentence,
  and the guide to open for the mechanics.
- **Open the guide before advising.** A row is a pointer. The mechanic, its conditions
  and its source are in the file and section named in the last column: load it before
  turning a row into a recommendation.
- **Rank by the reader's estate.** A change matters when the estate uses the service.
  Ask which providers and services are in scope, or rank by where the spend is, before
  reading out a whole month.
- **No prices here.** Rows state mechanics and ratios. For a current rate, use a live
  pricing tool if one is connected in the session, otherwise the provider's pricing
  page.

**Scope.** A change enters this digest when the library applied it: it was read on the
provider's or vendor's own page, and the last column names the guide that now carries
it. The weekly scan behind it follows provider release notes, billing changelogs,
pricing pages and FinOps Foundation publications. An announcement with no effect on
cost, or one not yet verified, is absent. Rows leave after 90 days; the guides keep the
mechanics. What the scan has seen and not yet verified is public, as the issues
labelled `content-update` at <https://github.com/OptimNow/cloud-finops-skills/issues>:
treat those as leads to check, not as facts.
